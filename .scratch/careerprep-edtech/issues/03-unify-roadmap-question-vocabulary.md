# 03 — Unify Roadmap / Question / Checkpoint / Mission vocabulary

Type: grilling
Status: open
Blocked by:

## Question

Merging Roadmap and Track collides four overlapping concepts. Settle the vocabulary before any schema is drawn, and write it into `CONTEXT.md`.

The collision:

- **Roadmap** (existing): published, ordered, admin-managed reading path with tree/accordion node views.
- **Mission** (existing, per `CONTEXT.md`): a `root` Question whose ordered children form one continuous investigation on a shared dataset.
- **Track** (proposed, then merged away): an ordered question sequence.
- **Checkpoint** (new): an auto-graded MCQ modal gating a Roadmap node.

Questions to settle:

- Is a Mission now a Roadmap node, a Roadmap in its own right, or a distinct thing that survives the merge?
- What is a Roadmap node called, and does it own content, questions, or both?
- Is a Checkpoint a Question with a role, or its own entity?
- Does "complete a node" mean read it, pass its checkpoint, or solve its attached Questions?
- What replaces the flat library — does it survive as a browse surface alongside Roadmaps, and what is it called?

Deliverable: updated `CONTEXT.md` glossary entries, each with its `_Avoid_` list.
