# A Concept is not a Question

Concepts — the four-part explanations (what it is, why it matters, how it works, an analogy) shown on a Step, in the solve workspace, and after a failed Checkpoint — live in their own `concepts` table, attached to Steps and Questions rather than stored as rows in `careerprep_questions`. The rejected alternative was a fifth `question_type` value, `'concept'`, which would have reused the existing admin screen, RLS policies and `(roadmap_id, step_slug)` attachment for free; we declined it because a Question is defined by having an answer to grade, and a whole subsystem leans on that being true — `start_assessment` draws its paper from that table, and `sync_exam_twin()` fires on every write to it.

**Consequences.** Concepts need their own table, policies, admin tab and attachment rows, which is real duplicated plumbing. In exchange, `careerprep_questions` keeps five NOT NULL columns that a Concept could only satisfy with empty strings (`content_md`, `industry`, `initial_sql`, `schema_sql`, `solution_sql`), the `careerprep_question_type` enum is untouched, and nothing that grades or certifies a learner has to learn about a row type that cannot be answered. Reopen this if Concepts ever gain an attemptable form.
